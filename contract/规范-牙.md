# 牙纪律（三条）

> 这不是文档规范，是**判据的判据**：一条测试如果违反下面任何一条，它就不算牙。

## 一、反向咬：把实现改坏，它必须红

```
做法：故意改坏一处（返回空、少一条、换个名字），跑该测试
要求：必红；不红就是假牙
```

反例（真发生过）：工具参数没转 JSON Schema，测试仍"全绿"——因为断言只看了名字。

## 二、跳 ≠ 绿

```
跳过的格，不许算进"通过"，也不许印"全过"
正确：X ✓ · Y 跳 · Z ✗
错误：X+Y ✓ · 0 ✗（把跳的算成绿的）
```

## 三、量不到 ≠ 0

```
量不到（读不到、超时、没权限）要印"未测/读不动"，不许写 0
0 是"量到了，结果是零"；两者结论完全不同
```

反例（真发生过）：`kgrep` 查不到端点，被写成"该能力 0 次"。

## 附：今天两次栽在这三条上

```
① 筛工具名用窄正则 → 三个工具没印出来 → 误判"只有两个"（量不到当 0）
② brief 在 → 推"apply 跑完 → 工具面没抛"（跳过代码顺序，跳当绿）
```
