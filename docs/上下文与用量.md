# 上下文与 Token 用量

> 这可能是全忆最实在的地方：**它不是把所有记忆塞进上下文，是每轮只递该递的几百字。**

## 每轮花多少

```
每轮注入    ≤ 600 token   （self 一页 + 相关日记 3 条 + 没清的账）
self.md     ≤ 400 token   （她是谁，固定一页）
每天沉淀    ≤ 1000 token  （写日记、抽承诺、抽判断）
```

**对比一下：**

```
把历史全塞进去      10 万 token 的会话 = 10 万 token 的账单，而且越用越贵
全忆每轮           ≤ 600 token，跟会话跑了多久无关
```

**所以它的成本不随记忆变大而上涨。** 卡带 5 千帧还是 5 万帧，每轮都是那几百字。

## 内存与速度（真机目标）

```
启动     < 100 ms     只读 manifest + self + 粗索引
常驻     < 80 MB      LRU 硬顶
单帧     < 20 ms
检索     < 1 s        中文大卡带实测 0.15–0.3 s
三年容量 ≤ 25 GB      纯文本 jsonl + zstd
```

## 它凭什么这么省

```
① 从不全量加载 —— 分片、按需、Buffer 而不是 string
② 布隆 + 偏移索引 —— 先判“有没有”，再只读那一片
③ 料由机器递 —— 不是把卡带塞给模型，是机器挑几句递上去
```

## 一句实话

**省 token 是结果，不是目的。**
目的是：**记忆可以无限长，而每一轮的开销几乎不变。**
不然用三个月就贵到不敢用了。
